OpenAIBOMThe problem

AI dependencies are more than packages.

Model references, loader settings and missing provenance can be scattered across a repository.

01 / VISIBILITY

What do we depend on?

Package declarations alone do not explain which model or dataset a source file references.

02 / REVIEW

What needs attention?

Mutable model references and permissive loading settings need traceable review—not a mystery score.

03 / CHANGE

Did the update help?

A release needs a comparison showing which findings appeared, disappeared or remain unresolved.

Built for: AI developers, engineering reviewers and teams demonstrating responsible release practices.

OpenAIBOMHow it works

From source files to inspectable evidence.

A local browser interface and Node.js engine. Selected source is parsed—not executed.

02 →

03 →

Inventory

04 →

Assess

Explicit rules, confidence, remediation and coverage gaps.

Baseline differences, observed graph, hashes and JSON export.

Runtime scanning is offline. No model inference, API key, source execution or external advisory request is required.

OpenAIBOMExplainable assessment

Clear decisions instead of an opaque score.

Fail

A blocking rule matched.

Examples: an unpinned model or explicit permission to load remote code.

Review

Evidence is incomplete.

Examples: dynamic options, unknown licenses, parse errors or missing local provenance.

Pass

Supported checks passed.

No blocking rule or review condition was found. This is not a safety guarantee.

Configuration checks

Model revision format; remote-code permissions; selected Python object-deserialization calls.

Synthetic advisory check

Exact fictional npm package/version match. Demonstrates the mechanism, not live CVE coverage.

Severity and confidence are separate. A configuration finding is not proof of exploitation.

OpenAIBOMInnovation in the prototype

The contribution is the evidence-to-change loop.

Not a claim to invent AIBOM. A focused combination that makes AI configuration review demonstrable.

STRUCTURED, NOT JUST TEXT

Syntax-aware discovery

Parses supported executable constructs and avoids treating comments or quoted examples as calls.

UNCERTAINTY IS VISIBLE

Honest policy decisions

Separates explicit violations from unresolved evidence instead of treating “not detected” as safe.

IMPROVEMENT IS INSPECTABLE

Reproducible comparison

Connects findings, observed references, input fingerprints and baseline changes in one report.

Why it is not a wrapper: the core work is implemented in parsers, deterministic rules, report comparison and a hand-labelled benchmark—not delegated to an LLM.

OpenAIBOMScope and trust

Useful evidence. Explicit limits.

What the prototype establishes

  • Observed references in supported syntax.
  • Declared package metadata and exact npm lock entries.
  • Policy matches and unresolved coverage.
  • Identity of selected input contents through hashes.
  • Differences between same-project reports.

What it does not establish

  • Real vulnerability-feed coverage or verified upstream licenses.
  • Training-data lineage or trusted model origin.
  • Scope-sensitive data flow or runtime reachability.
  • Model fairness, hallucination or prompt-injection resistance.
  • Signed attestations or SPDX / CycloneDX compliance.

Input hashes are unsigned, not provenance certificates. A finding can disappear because a file was removed or unparseable—check coverage before calling it fixed.

A pass is bounded to supported checks—not universal safety09 / 12
OpenAIBOMPresentation and deployment

Render-ready. Samples and visitor uploads.

One Node web service. No database, API key or paid model service required.

BUNDLED DEMONSTRATION

Try without uploading

Run risky and fixed samples, compare findings and inspect the benchmark. No visitor source is needed.

CONSENT-GATED UPLOADS

Inspect your own project

Public mode discloses server-side processing before upload. Source stays in application memory and is never executed.

BOUNDED PUBLIC SERVICE

Controls, not a guarantee

Host and origin checks, upload and rate limits, two concurrent scans and a 10-second worker deadline.

Privacy: never upload secrets or confidential source. Consent is not authentication; the hosting provider may retain request metadata.

Prepared and locally tested; no live deployment claimed. Render Free may sleep and cold-start. Publish the repository, then deploy its Blueprint.
